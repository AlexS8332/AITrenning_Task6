# Агент-справочник по животным (DeepSeek, Go + браузер)

Локальное приложение с веб-интерфейсом, в котором запускаются агенты.
Агент получает название животного, ищет сведения по внешним источникам
через инструменты и собирает карточку: название, латинское название,
описание, по выбору — классификационное дерево, среда обитания, питание.
Результат и журнал работы агента показываются в разных панелях.

Источники: русская Википедия (поиск и чтение статей по разделам) и
таксономическая база GBIF (сверка латинского названия, дерево
классификации, народные названия). Ключей к ним не нужно. Модель —
`deepseek-v4-flash` через API DeepSeek, вызов инструментов в
OpenAI-совместимом формате, температура 0, режим размышлений выключен.

## Три типа агентов

| Тип | Кто работает | Что делает |
|---|---|---|
| **Команда агентов** | координатор, идентификатор, систематик, специалисты по среде обитания и питанию | координатор запускает идентификатора, затем параллельно специалистов по выбранным опциям и склеивает карточку |
| **Один агент с инструментами** | один агент | сам ищет статью, сверяет латынь с GBIF, читает нужные разделы и отдаёт карточку одним вызовом |
| **Чат без инструментов** | один вызов модели | ответ из памяти модели; точка отсчёта для сравнения |

Агенты с инструментами работают только по данным инструментов. Завершающий
инструмент проверяет результат по журналу вызовов: карточка с латинским
названием, которое никто не сверял через GBIF, или пересказ раздела, который
никто не читал, отклоняются с объяснением, и модель исправляется. Так
ответ по памяти не проходит, даже если выглядит правдоподобно.

## Что нужно

- Go 1.22 или новее;
- ключ DeepSeek API (https://platform.deepseek.com);
- доступ в интернет к `ru.wikipedia.org` и `api.gbif.org`;
- любой современный браузер.

## Запуск

```bash
git clone https://github.com/AlexS8332/AITrenning_Task6.git
cd AITrenning_Task6
cp .env.example .env     # и вписать свой ключ в DEEPSEEK_API_KEY
go run .                 # поднимет сервер и откроет браузер
```

Флаги:

```bash
go run . -addr 127.0.0.1:9000   # другой адрес и порт
go run . -addr 127.0.0.1:0      # свободный порт, программа напечатает какой

go run . -out прогоны.md        # другой файл результатов
go run . -append                # копить прогоны в файле, а не перезаписывать
```

Ключ берётся из переменной окружения `DEEPSEEK_API_KEY` или из файла `.env`
(`.env.local`) в рабочем каталоге или выше по дереву. В git эти файлы не
попадают. Остальные переменные необязательны, см. `.env.example`.

## Интерфейс

1. **Запрос**: название животного, тип агента, три флажка опций.
2. **Результат**: карточка животного. Заполняется по мере работы: в команде
   сначала появляются название и описание, затем дерево и разделы по мере
   ответов специалистов. Если сведений нет, так и написано, без карточки.
3. **Журнал**: лента событий с фильтром по агентам и видам событий. Каждый
   запрос к модели, каждый вызов инструмента с аргументами и результатом,
   отказы завершающего инструмента, токены и стоимость шага. Внизу итоги
   прогона: время, число запросов, вызовов, токены, стоимость по прайсу
   DeepSeek с учётом тарифа по времени суток.
4. **Промпты**: что получила модель на старте каждого агента. Системный
   промпт, первое сообщение и инструменты с описаниями, как они уходят
   модели; у команды по записи на каждого агента.

Прогон живёт на сервере: страницу можно перезагрузить, идентификатор прогона
в адресе. Результат уходит в `results.md`: запрос, агент, опции, карточка,
счётчики, промпты и таблица журнала. Файл можно посмотреть кнопкой
«Показать отчёт».

## Как устроено

```
main.go                   запуск: флаги, ключ, сборка инструментов и агентов, сервер
internal/llm              клиент DeepSeek: сообщения, tools, tool_calls, usage, прайс
internal/tools            Tool, реестр, HTTP с кэшем; инструменты Википедии и GBIF
internal/agent            контракты: Task, Result, Event, Emitter, Agent; Runner — цикл «модель, инструменты»
internal/agents           агенты: chat, solo, team (координатор и четыре агента); каталог типов
internal/runs             прогон: состояние, журнал, подписчики SSE, файл результатов
internal/server           HTTP API: /api/agents, /api/runs, /api/runs/{id}/events, /api/report
web/                      страница, стили, скрипт без сборки; markdown-рендер вшит
```

**Агент** описывается пятью частями: роль (системный промпт), модель,
набор инструментов, лимиты (шаги) и завершающие инструменты с проверкой
результата. Общий цикл в `Runner`: запрос к модели, если пришли вызовы
инструментов, исполнить их и вернуть модели, повторить; если модель вызвала
завершающий инструмент, проверить аргументы и отдать результат. Каждый шаг
публикует событие в журнал.

**Команда**: координатор написан кодом, а не промптом. Опции уже определяют,
кого звать, а детерминированный порядок проще проверить и объяснить по
журналу. Координатор сам реализует интерфейс `Agent`, так что вложенность
команд ничего не стоит. Специалисты работают параллельно, каждый со своим
трекером вызовов, и их ошибки становятся оговорками в карточке, а не
роняют прогон.

**Инструменты** возвращают JSON-текст: он уходит модели как есть и в журнал
для человека. Википедия читается по разделам: сначала вступление и
оглавление, затем нужный раздел, чтобы не заливать модели статью целиком.
Ответы источников кэшируются на время работы процесса.

## API

```
GET  /api/agents               типы агентов и путь к файлу результатов
POST /api/runs                 {agent, query, options:{classification,habitat,diet}} → 202 и состояние
GET  /api/runs/{id}            состояние и журнал
GET  /api/runs/{id}/events     поток SSE: snapshot, затем state и log раздельно, в конце done
GET  /api/report               файл результатов целиком
```

## Тесты

```bash
go test ./...
go test -race ./...
```

Сеть не нужна: модель подменяется сценарием, Википедия и GBIF —
подставными серверами. Проверяются клиент API, разбор статей и ответов
GBIF, цикл агента с инструментами и отказами, команда целиком, файл
результатов, HTTP-маршруты и поток событий.
